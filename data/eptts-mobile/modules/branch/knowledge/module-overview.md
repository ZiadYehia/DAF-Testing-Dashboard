# Branch — Module Overview

## Overview

The Branch module represents the warehouse/storage-facility tier of the EPTTS mobile app's serialized pharmaceutical supply chain (Manufacturer -> Distributor -> Branch -> Pharmacy -> Patient). A Branch account (e.g. testbranch@eptts.com, Admin@123456) sits mid-chain: it receives bulk shipments upstream from manufacturers/distributors into its own warehouse inventory, and it dispatches outbound shipments downstream to pharmacies. It also participates in the returns chain both as an initiator (Manufacturer Return, sending packs/SSCCs back up to the manufacturer) and as a receiver (Incoming Returns, accepting returns sent down from pharmacies). Every action (shipping, receiving, unpacking) is submitted as an EPCIS event to the national EPTTS registry ('Masar'), viewable in the Branch's own EPCIS History log. The Branch role has the largest tile set of all staff roles (7 tiles) because it exposes both supply-side (upstream) and demand-side (downstream) operations plus account-management actions (Delete Account, Logout) not shown on the Distributor home grid.

## Roles involved

Branch staff user — logs in via Keycloak Sign In with a branch account (e.g. testbranch@eptts.com / Admin@123456); the branch's registered GLN entity name is shown in the home header as 'Hello / <Branch name>' (e.g. 'Hello / Main warehouse'). No separate sub-roles or permission tiers are documented within the Branch module itself — all branch users see the same 7-tile home screen and have access to all branch operations (create/receive shipments, all 3 return sub-flows, EPCIS history, delete account, logout).

## Business rules

Shipment statuses: Draft (editable, packs can be added/dispatched), Dispatched (read-only until confirmed as delivered by recipient; only status from which 'Cancel Shipment' is available), Delivered (fully read-only), Partially Delivered (result of a partial scan at receive time). Return statuses: PENDING (awaiting action by receiving party; requires Confirm Return or Cancel Return before further action), CONFIRMED (green badge, read-only, has a Confirmed timestamp), CANCELLED (red/pink badge, read-only, cannot be reactivated). Return numbering: RET-YYYY-NNNNNN (sequential) or AGENT-RTB-<UUID> (agent-generated) per platform-wide convention. EPCIS event statuses: Completed (green) or Failed (red); Failed events carry a structured error (error code such as INTEGRITY_ERROR + human-readable message) surfaced only via a bottom-sheet, never a full-page navigation. Validation rules for Create Shipment: Destination GLN is required (cannot create draft without a valid selection; GLN not found shows a 'no results' state in the autocomplete) and ERP Invoice Number is required (cannot be blank); duplicate invoice numbers should trigger a system warning; network errors should show a graceful error with retry. Receive Shipment scan validation: scanning a barcode not on the invoice manifest or a duplicate scan should produce an error/warning (documented generically per platform pattern, not explicitly re-verified for Branch but called out as 'same as Distributor Receive Shipment'). Returns validation: PENDING incoming returns require branch action (Confirm/Cancel) before they expire; CANCELLED returns cannot be reactivated. Note fields on both Manufacturer Return and returns generally are optional and must not block submission when empty. Cancel Shipment is scoped strictly to Dispatched-status shipments — the button does not appear for Draft or Delivered shipments.
