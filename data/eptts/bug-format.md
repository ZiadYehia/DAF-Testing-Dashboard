# Bug Report Format

## Required sections

Bug reports (both the bugs/_template.md and actual bugs/**/*.md files) use YAML frontmatter followed by a structured markdown body. Frontmatter fields: title, status (draft | reported), jira_key (DW-### or null), reported_at (ISO timestamp or null), feature (matches the feature folder name, e.g. receive, sell, return, return-to-distributor, queue, transaction-processing, product-catalog-sync, authentication), priority, bug_type. Body sections in order: a descriptive H1 title (no vague words) or Summary paragraph (1-3 paragraphs describing what's broken, context, and why it matters — including serialization/sync/offline context when relevant) — divided by '---' horizontal rules — then: 'Steps to Reproduce:' (numbered list, e.g. Open the Agent application → Navigate to Module/Screen → Action → Action → Observe X), 'Expected Result:' (one clear sentence), 'Actual Result:' (one clear sentence), 'Environment:' (Windows version, Agent Version X.X.X, Online/Offline state), 'Priority:' (repeats the frontmatter priority value), 'Bug Type:' (repeats the frontmatter bug_type value). Real bug files sometimes use a plain 'Summary:' label instead of an H1, and environment is sometimes written as a bulleted list ('- Platform: Windows 10/11', '- App: Masar Agent v2.x.x', '- Internet connection: Available') rather than the template's three plain lines — both forms are acceptable/observed.

## Severity / priority conventions

Priority field uses 4 levels: P1 – Critical, P2 – High, P3 – Medium, P4 – Low (in practice bug files use both the full 'P2 – High' form and bare 'P1'/'P2'/'P3' shorthand — the full em-dash form is the canonical template value). Bug Type field is a closed set: Functional | Functional / Integration | Functional (Backend/API) | Functional — Intermittent / Flaky | UI/UX. Status field values observed: draft (not yet filed in Jira, jira_key/reported_at are null) and reported (has a jira_key like DW-801, DW-804 and a reported_at ISO timestamp). EPTTS and Dawana share the same Jira board, so bug/Jira keys use the shared 'DW-' prefix (not an EPTTS-specific prefix) regardless of which app the bug came from. Test-case Attachment column mirrors this: Fail status requires one or more space-separated DW-### keys.
